# 投递表单未保存保护设计

## 背景

投递管理页的主表单、跟进时间线和提醒字段都直接绑定到页面状态。当前按 `Esc`、点击“取消编辑”或切换视图时会立即重置主表单，用户输入会静默丢失。简历编辑页已经具备一致的脏状态提示，因此投递管理页需要补齐同等级的保护。

## 目标

- 在用户修改投递表单后，阻止无意的取消或离开造成输入丢失。
- 覆盖主投递字段、时间线新增字段和提醒时间。
- 保持现有保存、删除、状态更新、加载锁和快捷键语义。
- 不新增后端接口、依赖或持久化草稿，降低数据迁移和隐私风险。

## 方案

采用轻量脏状态基线：进入编辑或开始填写新记录时记录表单快照，实时比较当前值与快照。存在差异时标记为 dirty。

### 状态

- `formBaseline`：主投递表单快照，初始为空表单。
- `followupBaseline`：时间线和提醒快照，在展开某条记录时建立；切换记录或完成保存后重置。
- `isDirty`：主表单或跟进字段任一快照不一致。
- `showLeaveConfirmation`：用户触发取消或离开快捷键后显示的页内确认。

### 交互

- 未修改时，“取消编辑”和 `Esc` 继续立即重置。
- dirty 时，取消操作不重置表单，显示页内 `role="alert"` 提示，提供“继续编辑”和“放弃并返回”。
- “放弃并返回”清理所有表单状态、关闭时间线确认，并恢复空表单。
- 保存成功后以服务端结果替换记录，清理 dirty 状态和确认提示。
- 保存失败保留原输入和 dirty 状态，错误提示继续使用现有 `ErrorNotice`。
- dirty 期间注册 `beforeunload`，浏览器关闭、刷新或离开时触发原生保护；干净时移除监听。
- 请求进行中时，取消和放弃按钮保持禁用，沿用现有 `pendingKey`/`loading` 锁。

### 可访问性与视觉

- 确认区域使用 `role="alert"` 与 `aria-live="polite"`，文案明确说明输入尚未保存。
- 操作按钮沿用 `AsyncButton` 和现有文字/危险操作样式，确保键盘可达和 44px 最小点击高度。
- 新样式只增加确认区域的布局、边框和背景，不改变页面主色或表单栅格；移动端允许按钮换行。

## 非目标

- 不实现本地草稿自动恢复。
- 不拦截列表筛选、状态下拉或删除确认之外的无关操作。
- 不改变时间线和提醒 API 的请求格式。

## 验收标准

1. 修改任一主表单字段后点击取消或按 `Esc`，输入仍保留并显示确认区域。
2. 选择继续编辑关闭提示；选择放弃后恢复空表单并清理编辑状态。
3. 修改时间线标题、说明、时间或提醒时间时，离开同样受到保护。
4. 成功保存、成功新增时间线事件或成功保存提醒后，对应 dirty 状态清零。
5. dirty 状态只在页面挂载期间注册 `beforeunload`，卸载时始终清理。
6. 现有投递工作流、键盘快捷键和构建测试全部通过。
