# Web 工作区连续性设计

## 目标

让 Web 工作区的当前页面和简历编辑上下文可通过 URL 恢复，并支持浏览器前进/后退，降低刷新或误操作造成的状态丢失感。

## 方案

- 使用 `?view=<workspace>&draft=<id>` 保存当前工作区页面和正在编辑的简历。
- 保持现有 `activeView` / `editingDraftId` 状态模型，不引入路由依赖。
- 侧边栏切换和打开简历使用 `history.pushState`；保存/取消编辑清除 `draft` 并回到简历列表。
- 浏览器 `popstate` 读取 URL 并恢复状态，页面标题随页面/编辑上下文更新。
- 导航守卫阻止离开时保留待处理目标，用户确认后继续导航。

## 范围

本轮包含 URL 解析/序列化、历史记录、popstate 恢复和标题；不包含结果缓存、组件 KeepAlive、后端导入和跨端同步。

## 验收标准

1. 无效或缺失的 `view` 默认进入概览。
2. `draft` 存在时恢复简历编辑器，并保留其他查询参数和 hash。
3. 页面切换可前进/后退，编辑上下文可通过刷新 URL 恢复。
4. 关闭或保存编辑后 URL 不再包含 `draft`。
