# Web 信任状态与恢复体验设计

## 背景与目标

上一轮已建立共享能力上下文和运行时测试，但 Jobs/Insights 仍把 `jobMatching` 简化为布尔值：演示服务看起来像真实服务，不可用模式仍可点击，能力刷新后可能残留旧错误提示。本轮完善岗位匹配与年度洞察的状态语义、恢复动作和运行时证据，提升用户对结果来源和下一步动作的确定感。

## 范围

只修改 `web-frontend/src/views/JobsView.vue`、`web-frontend/src/views/InsightsView.vue`、`web-frontend/src/styles/base.css` 及相关测试。保留现有共享能力上下文和 API endpoint/payload，不修改后端、支付协议、主题持久化、移动端导航或其他 Demo 文案。

## 三态能力呈现

Jobs 和 Insights 读取 `jobMatching` 的完整 `enabled`、`mode`、`notice`：

- 加载中：健康状态未确认时，专业模式显示“检查中”并不可提交；简化模式保持可用。
- 真实可用：专业模式显示“专业版”，结果沿用现有结构。
- 演示可用：`mode === "demo"` 时，模式和结果显示“专业版（演示）”，结果顶部增加中性来源说明，明确为本地/演示数据，不代表实时职位或真实市场洞察。
- 不可用：专业模式使用原生 `disabled`，通过 `aria-describedby` 关联原因文本，不能被点击选中；简化模式和基础表单保持可用。

专业入口始终保留，只有不可用时禁用，不在点击后才暴露状态错误。

## 恢复动作与同步

模式区直接展示不可用原因和两个恢复动作：

- “重试服务状态”调用 App 共享 `refresh()`，使用共享 `refreshing` 防止并发。
- “查看会员权益”沿用 `navigate('membership')`。

重试成功后清除旧 capability error；失败保留最新原因。恢复成功不自动重复用户之前的查询，用户主动再次提交才执行。能力从可用变为不可用时，若当前模式为专业版，自动切回简化版并保留输入内容；从不可用恢复时移除禁用状态和说明。

## 视觉与可访问性

新增 `.mode-notice` 的中性背景、边框、间距和可读颜色；`.is-unavailable` 的禁用样式优先于选中样式，使用降低对比度和禁用光标。Demo 说明使用信息色，不使用成功绿或购买促销色。模式按钮使用真实 `disabled` 与 `aria-describedby`，重试按钮具备可访问名称和 loading 状态。

## 运行时测试

扩展 jsdom 挂载测试：

- `mode === "demo"` 时 Jobs/Insights 的模式和结果来源标签包含演示语义。
- `jobMatching` disabled 时专业按钮具有原生 `disabled`，无法切换或提交，原因文本可见，重试和会员导航事件可触发。
- 共享刷新成功后两个消费者同步移除禁用样式和旧错误；刷新失败保留旧状态。
- 能力降级时自动从专业模式回退到简化模式且不清空岗位/年份输入。
- 受保护请求断言按调用路径过滤，不使用会漏掉省略参数的 `expect.anything()`。

保留现有源码契约、纯函数测试和完整构建验收。

## 验收标准

1. Demo 能力、真实能力和不可用能力在模式按钮、结果标签和来源说明中可区分。
2. 不可用专业模式具备原生 disabled、原因关联和直接恢复动作，不会被选中或发起查询。
3. 共享刷新成功/失败在 Jobs 与 Insights 间一致，旧错误不会残留，输入内容不丢失。
4. 简化模式、密码登录、套餐/订单和后端 403 行为保持不变。
5. 运行时测试、完整 Vitest、生产构建和 `git diff --check` 全部通过。

## 非目标

不新增后端字段、不改变 API 协议、不处理移动端抽屉无障碍、不实现主题持久化、不改其他页面的 Demo 文案或整体视觉系统。
