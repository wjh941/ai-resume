# Web 能力状态与信任闭环设计

## 背景与目标

Web 前端目前直接暴露短信登录、支付、专业岗位匹配和专业报告等可选能力，服务未配置时通常要等请求失败后才反馈。后端已经通过 `/health.data.features` 提供能力元数据。本轮将这些元数据接入 Web，在用户进入动作前给出稳定、真实、可恢复的状态，同时保持简历编辑、保存和基础评估等核心流程可用。

## 范围

本轮只改 `web-frontend` 与对应测试，不修改后端业务接口。能力范围为：`resume_import`、`sms_login`、`wechat_oauth`、`payment`、`push_notifications`、`job_matching`。主题持久化、移动端抽屉无障碍和其他独立体验问题不纳入本轮。

## 架构与数据流

新增 `web-frontend/src/lib/capabilities.ts`，复用小程序现有能力模型：每项能力包含 `enabled`、`mode`（`real`、`demo`、`disabled`）和 `notice`。映射器只接受结构有效的布尔值、合法模式和非空说明；字段缺失、非法值或响应不是对象时，该能力回落为 disabled。请求 `/health` 失败时，整体回落为默认 disabled 状态。

`App.vue` 在启动时非阻塞请求一次能力状态，并通过 Vue `provide/inject` 注入能力引用。页面不重复请求，也不等待能力请求完成后才渲染。能力状态只控制可选入口的呈现与提交前校验，后端仍是最终权限来源。

## 交互与文案行为

所有受影响入口使用三种可见状态：

- 可用：正常操作并展示成功结果。
- 演示：允许操作，但按钮和结果明确写出演示语义；演示支付只调用现有演示回调，不宣称真实扣款。
- 暂不可用：入口保留但置灰、不可提交，显示能力提供的原因，并提供重试能力状态或前往会员等恢复动作。

登录页默认密码登录。短信标签保留但禁用，说明短信服务暂未配置；不可用状态不触发发送验证码请求。

会员页继续展示套餐、权益和订单。支付 disabled 时支付按钮不可用并显示原因；payment 为 demo 时按钮明确标注“演示支付”。任何不可用状态都不进入伪造成功流程。

岗位匹配保留基础/演示查询。需要外部或专业服务的模式在提交前校验状态；不可用时不发起请求，展示原因和恢复动作。简化报告继续可用，专业报告在服务或权限不足时提前阻断；若后端仍返回 403，沿用现有会员恢复提示。

能力请求失败只影响受影响的可选入口，不阻塞核心工作区。重试按钮有进行中状态，避免并发重复请求；错误文案不使用虚假倒计时、强制购买或夸大承诺。

## 组件边界

- `lib/capabilities.ts`：默认值、类型、健康响应映射、能力查询和重试请求。
- `App.vue`：初始化并提供能力状态，不承载页面业务判断。
- `components/LoginPanel.vue`：短信入口的状态与说明。
- `views/MembershipView.vue`：支付模式、禁用态和演示标记。
- `views/JobsView.vue`：匹配模式提交前能力校验。
- `views/InsightsView.vue`：专业报告提交前能力校验与恢复动作。

页面只消费能力接口，不直接读取 `/health` 或后端字段名。核心 API 的现有加载、错误和权限处理保持不变。

## 测试与验收

新增能力映射单元测试，覆盖完整响应、缺字段、非法模式、空说明和网络失败回退。组件/交互测试覆盖短信禁用且不调用发送接口、支付 disabled/demo 两种状态、专业报告提前阻断、重试进行中状态和现有 403 恢复路径。保留现有 Web 测试并运行完整 Vitest、生产构建和 `git diff --check`。

验收标准：

1. `/health` 成功时各入口与 `features` 状态一致。
2. `/health` 失败或响应畸形时页面仍可进入，核心简历流程可用，可选入口均有明确 disabled 说明。
3. disabled 状态不会发送短信、支付或专业报告请求；demo 状态不会被标成真实服务。
4. 后端 403 仍显示现有权限恢复提示，前端预检不会替代后端鉴权。
5. 测试、构建和差异检查全部通过。

## 非目标

不新增后端能力、不改变支付/认证协议、不复制会员权限规则到前端、不隐藏套餐或订单历史、不实现主题持久化，也不在本轮修改移动端导航无障碍。
