# 岗位目录、专业匹配与合规市场信息设计

**日期：** 2026-08-07  
**状态：** 已确认设计，等待规格审阅

## 目标

将当前小规模岗位目录升级为可扩展的求职岗位知识库，并在岗位分析中加入专业匹配与跨专业路径，帮助用户从“我学什么专业”进入到“我适合哪些岗位、还缺哪些能力”的决策流程。

第一阶段覆盖约 200 个核心岗位，按岗位族谱扩展，不承诺将市场上所有临时命名的职位一次性硬编码进本地数据库。

## 合规数据边界

不实现 BOSS 直聘、实习僧或其他招聘平台的爬虫、批量抓取、绕过登录、绕过反爬或镜像职位库功能。

岗位目录数据采用以下来源：

1. 维护型本地岗位目录：人工整理岗位名、别名、所属大类、技能与专业关联规则。
2. 用户主动触发的联网市场更新：调用已接入的搜索提供商，展示公开网页来源摘要和链接。
3. 获得书面许可或官方 API 后：新增独立提供商适配器，不改变目录、分析和简历生成的主流程。

联网内容用于辅助核验市场信号，不作为自动生成候选人事实、薪资承诺或职位数据存档。

## 岗位目录

### 目录规模与结构

第一阶段建立 12 个岗位大类、约 200 个核心岗位：

1. 软件研发
2. 人工智能与算法
3. 数据与数据平台
4. 测试与质量工程
5. 云计算、运维与安全
6. 产品、项目与解决方案
7. 设计与内容创意
8. 市场、品牌与增长
9. 运营、电商与客户成功
10. 销售、商务与供应链
11. 财务、法务、人力与行政
12. 机械、电子、制造、能源与生物医药

每个岗位保留：

- 标准岗位名称
- 所属岗位大类
- 常见别名与模糊搜索关键词
- 典型学历与专业门槛
- 核心技能、加分技能与初级可替代技能
- 相近岗位、转岗路线和适合实习的岗位
- 本地数据版本与最后维护时间

`job_catalog` 保留为快速搜索索引。新增的岗位知识使用独立服务层读取，避免将复杂专业规则塞入现有搜索逻辑。

### 搜索体验

- 输入“数据”显示数据工程师、数据分析师、数据库运维工程师、数据清洗专员、数据标注专员、数据质量工程师、数据治理工程师等。
- 输入任意关键词显示标准岗位与所属大类。
- 用户可选择 1 至 3 个岗位分别查看，不将相近岗位的技能、薪资或职责混为同一个岗位。
- 不在搜索阶段自动请求联网服务，避免卡顿和无意义的外部调用。

## 专业匹配流程

岗位咨询流程调整为：

`岗位搜索 -> 求职身份 -> 所学专业 -> 岗位与专业联合分析`

专业输入支持：

- 常见专业下拉分组
- 手动输入专业
- “跨专业/专业不限”选项

同一会话保存专业信息；用户可在后续岗位查询时修改。

### 匹配输出

岗位分析新增“专业与岗位匹配”模块：

- 匹配等级：高度匹配、可迁移、需要补齐、跨度较大
- 可复用课程、项目、实验、社团和通用能力
- 缺失技能的高优先级清单
- 不编造经历的 7 天、30 天学习与作品准备任务
- 更适合作为首投、保底或转行过渡的相关岗位

简历生成会根据专业补充两条项目草案与一条实习草案的表述方向，但仍只生成 `[待确认]` 内容，不替代真实经历。

## 联网市场信息

保留已实现的 Tavily 可选客户端，默认禁用。

启用后：

- 用户在岗位结果页主动点击“联网更新”。
- 后端查询公开网页，返回来源标题、链接、摘要与可选发布时间。
- 前端展示来源卡片，并提供复制链接。
- 搜索错误或没有配置密钥时，返回可读说明并保留本地分析。

新增的后续提供商必须实现统一接口：

```python
async def search(query: str) -> MarketSearchReport: ...
```

不得在前端保存或暴露任意搜索提供商的密钥。

## 前端体验

岗位搜索页增加专业步骤卡：

- 身份选择完成后展示专业选择，不直接跳到长篇岗位结果。
- 显示当前身份、专业与目标岗位的简洁摘要。
- 专业匹配、岗位深度分析、身份方案和市场来源分别按模块折叠。
- 岗位联想和专业搜索均采用下拉推荐层，支持手动输入。

页面维持现有浅色移动端工作台风格，保证中文岗位名、专业名和长标签自动换行，避免截断。

- 验证身份后出现专业步骤。

- 验证简历自动补全仍只在空经历时生成 2 条项目和 1 条实习草案。

回归：

- 既有岗位分析、简历批改、草稿、导出、CSV 接口和可选联网搜索测试必须继续通过。
