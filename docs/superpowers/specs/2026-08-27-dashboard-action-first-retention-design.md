# Dashboard Action-First Retention

## Goal

把独立 Web 工作台的 Dashboard 从三项计数升级为“今日行动台”：用户进入后能快速理解当前阶段，并在低认知负担下开始一个真实、可完成的下一步。

## Audience And Mode

面向正在整理简历、规划方向或跟进投递的求职者。用户通常没有明确的下一步，或在多项任务之间来回切换。页面采用 Operate 模式，优先清晰、可执行和可恢复，不追求游戏化刺激。

## Design Direction

- 首屏只设置一个主焦点：“今天先完成这一件事”，由已有任务、投递和简历数据推导。
- 右侧显示简历准备、职业规划、投递执行三条状态线，使用“未开始 / 进行中 / 已完成”，不编造百分比或排名。
- 下方最多列出三条“继续推进”记录，提供进入对应工作区的直接动作。
- 无数据时显示三步启动清单；加载、错误和空状态保持明确的反馈与重试入口。
- 使用目标梯度、降低选择成本、即时完成确认和回访线索促进持续使用；不使用排行榜、强制签到、倒计时、虚假成就或焦虑文案。

## Data And Rules

扩展现有 `loadOverview` 的返回模型，继续复用 `/api/applications`、`/api/draft/list` 和 `/api/career/tasks`，不新增后端端点。

焦点行动按以下确定性规则选择：

1. 优先选择已逾期或最近到期的未完成职业任务。
2. 其次选择有近期下一步日期的投递记录。
3. 没有草稿时引导创建第一份简历。
4. 有草稿但没有行动任务时引导补充职业规划。
5. 数据完整且无紧急事项时显示复盘或查看投递记录。

所有候选内容必须来自 API 返回数据；缺少字段时降级为通用中文提示，不生成事实性结论。

## Interaction And Accessibility

- 主按钮执行已有导航事件，不改变业务 API。
- “换一件”只在存在多个候选行动时出现，并保持确定性轮换。
- 主要区域使用清晰的标题层级、`aria-live` 状态反馈和可聚焦按钮。
- 加载时保留稳定骨架尺寸；错误时提供可重复的刷新动作。
- 桌面布局保持双列层次，窄屏改为单列，按钮和文本不得溢出。

## Testing And Boundaries

- 为焦点选择和三条状态线添加纯函数单测，覆盖逾期、空数据、缺失字段和并列候选。
- 为 OverviewView 添加结构契约测试，确保主焦点、状态反馈、空状态和导航入口存在。
- 通过 Web Vitest、TypeScript、Vite build 和 Impeccable detector 检查回归。
- 本轮不实现运营监控、支付、推送、外部岗位抓取或新的留存积分系统。
