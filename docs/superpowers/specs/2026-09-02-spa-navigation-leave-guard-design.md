# SPA 导航未保存保护设计

## 背景

投递管理页已经可以识别主表单、时间线和提醒的未保存状态，也能拦截 `Esc`、取消、删除和浏览器关闭。但工作台侧栏由 `App.vue` 直接切换 `activeView`，会在 dirty 时卸载投递页，绕过页面内确认。

## 目标

- 统一拦截侧栏和工作台内部发起的 SPA 视图切换。
- dirty 时保留当前页面和输入，显示投递页已有确认区域。
- 用户选择“放弃并返回”后继续刚才点击的目标视图；没有待处理目标时只完成当前放弃操作。
- clean 或没有守卫时保持现有即时切换行为。

## 方案

在 `App.vue` 创建并 `provide` 一个轻量导航守卫上下文。当前视图通过 `register` 注册同步 `canLeave` 函数并取得注销函数；父级所有 `navigate` 事件统一进入 `requestNavigation`。

- `requestNavigation(view)` 忽略当前视图，调用守卫；守卫返回 `false` 时记录最新目标视图并保持当前视图不变。
- `ApplicationsView` 的 `canLeave` 在 dirty 时显示现有 `showLeaveConfirmation`，返回 `false`；clean 时返回 `true`。
- `ApplicationsView` 放弃修改后发出 `navigation-ready`，父级消费待处理目标并完成一次切换。
- 守卫注销后清理引用，避免异步视图卸载后拦截后续导航。

## 可访问性与视觉

- 复用现有 `role="alert"`、`aria-live="polite"` 确认区域和按钮，不新增模态框。
- 侧栏按钮的 `aria-current`、抽屉关闭和键盘行为保持不变。
- 不新增颜色、动效或布局结构；只补充导航状态的测试契约。

## 边界与非目标

- 本轮只保护投递管理页的 SPA 导航；简历编辑器的离开流程保持现状。
- 不持久化待处理目标，不改变后端 API，不拦截当前视图重复点击。
- 多次点击不同目标时只保留最后一个目标，用户确认后进入最后点击的视图。

## 验收标准

1. dirty 投递页点击侧栏或内部导航事件时，`activeView` 不变且显示确认提示。
2. clean 投递页导航一次完成，侧栏和抽屉行为不回归。
3. 点击“继续编辑”保持当前视图；点击“放弃并返回”进入最后一次被拦截的目标视图。
4. 守卫组件卸载后不再拦截导航，注册/注销引用不会泄漏。
5. 导航上下文单元测试覆盖 clean、dirty、注销和多次目标覆盖；Web 全套测试与构建通过。
