# 联网岗位搜索与简历生成体验设计

**日期：** 2026-08-07  
**状态：** 已批准，自动执行

## 目标

从求职者使用视角补齐三个关键体验：

1. 输入模糊岗位词时快速看到可选的关联岗位，能够多岗位分别分析。
2. 空白简历可获得 2 至 3 条与目标岗位相关、但明确标记待确认的内容草案。
3. 在不配置密钥时仍可正常使用本地目录；配置密钥后可主动请求联网市场信息，查看来源摘要。

本次不修改简历草稿、CSV、导出服务与既有岗位分析接口的数据格式。

## 求职者体验

### 岗位联想

- 输入“数据”立即出现下拉式关联岗位：数据工程师、数据分析师、数据库运维工程师、数据清洗专员、数据标注专员等。
- 用户可选 1 至 3 个岗位，在同一页面切换不同岗位的分析结果。
- 结果页清晰展示当前岗位、关键技能与薪资摘要，避免长文本开始前没有重点。

### 联网更新

- 本地目录始终可用，负责即时联想与无网络的 Demo 使用。
- “联网更新”是用户主动点击的可选动作，不在输入时自动消耗外部 API 配额。
- 配置 `WEB_SEARCH_PROVIDER=tavily` 与 `TAVILY_API_KEY` 后，后端调用 Tavily Search 获取公开网页结果，前端展示标题、摘要和来源地址。
- 未配置密钥时接口仍返回成功响应，明确说明“尚未配置联网搜索”，而不是报错。
- 联网内容只作为市场信息来源，不替换既有 AI 岗位结构化分析，也不将来源内容写入草稿。

### 简历智能补全

- 当项目经历为空时，按目标岗位加入两条不同侧重点的项目草案。
- 当实习/工作经历为空时，加入一条实习草案。
- 所有未知公司、时间、职责边界与量化结果均保留 `[待确认]`，并在界面说明需要用真实经历替换。
- 已填写的项目和工作经历绝不覆盖；已有一类内容时不重复追加该类草案。

## 技术设计

### 本地岗位目录

扩充 SQLite `job_catalog` 的固定初始化数据，增加数据分析、数据库运维、数据清洗、数据标注、数据质量和数据治理相关岗位及别名。`JobCatalog.search()` 不变，继续根据岗位名与别名排序匹配。

Mock AI profile 为新增典型岗位提供不同的职责与技能组合，以确保选中不同岗位会得到不同结果。

### 联网搜索服务

新增 `app/services/web_search.py`：

- `MarketSource`：标题、URL、摘要、可选发布时间。
- `MarketSearchReport`：是否已启用、提供商、提示文案、来源列表。
- `DisabledWebSearchClient`：默认实现，无密钥也不触发网络请求。
- `TavilyWebSearchClient`：使用现有 `httpx` 发送 `POST /search`，采用 `Authorization: Bearer <key>`。
- `build_web_search_client(settings)`：根据环境配置返回相应实现。

新增只读接口：

`GET /api/job/market-search?role_name=<岗位名>`

该接口只返回来源摘要，失败时降级为可读提示而不影响岗位查询与简历生成。

配置项：

```env
WEB_SEARCH_PROVIDER=disabled
TAVILY_API_KEY=
WEB_SEARCH_BASE_URL=https://api.tavily.com
WEB_SEARCH_MAX_RESULTS=5
```

### 前端信息层级

- 岗位输入区使用相对定位的下拉建议面板，不再像普通内容卡片堆叠。
- 已选岗位保留胶囊标签和最多 3 个的限制。
- 分析结果增加摘要区、按需折叠的长内容区，以及“联网更新”来源区。
- 样式沿用现有浅色设计，但提升标题层级、卡片边界、按钮反馈与移动端间距，确保文本换行而非截断。

### 兼容性

- 不要求外部搜索密钥；默认配置下应用可本地完整运行。
- 前端不会直接保存或暴露 API Key。
- 既有 `/api/job/query`、咨询、草稿、导出、CSV 相关接口保持兼容。
