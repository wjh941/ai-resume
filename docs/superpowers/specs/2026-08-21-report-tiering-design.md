# 报告分层与岗位年度就业洞察设计

## 目标

为桌面 HTML 仪表盘中的建议与分析结果提供一致的“精简版 / 专业版”体验。精简版面向所有登录用户，使用清晰、低认知负担的语言给出结论和下一步；专业版仅向有对应会员权限的用户提供，补充个人证据、年度资料、适用边界和更具体的行动指导。

首轮仅覆盖 `premium-dashboard.html`。现有 UniApp H5 端后续通过相同 API 接入，不在本轮重复实现界面。

## 范围

本轮覆盖仪表盘直接使用的下列建议和分析输出：

- 岗位情报：`/api/job/query`
- 岗位匹配：`/api/job/match`
- 职业规划：`/api/job/plan`
- 职业测评：`/api/career/assessment` 与 `/api/career/assessment/submit`
- 简历建议：`/api/resume/ai-rewrite`
- 年度就业洞察：新增按岗位查询的读取接口

不实现招聘网站爬虫、实时岗位数量或薪资数据、外部招聘数据同步。专业版中的市场相关表达必须带资料来源和适用范围，不把模型推断表述为实时市场事实。

## 统一报告契约

所有上述接口维持现有请求、响应字段和默认行为，新增可选请求参数 `report_mode`：

- `simplified`：请求精简版。
- `professional`：请求专业版；无相应会员权限时，后端返回精简版。
- 未传递：保持现有接口的默认行为，避免影响已有客户端。

在原有响应对象中追加 `report`，不替换任何现有字段：

```json
{
  "report": {
    "mode": "simplified",
    "summary": "适合先补齐数据分析项目证据，再投递初级数据分析岗位。",
    "actions": ["整理一个 SQL 分析项目", "对照 3 份目标 JD", "更新简历技能栏"],
    "evidence": [],
    "source_notice": "基于已验证个人资料和本地年度资料生成，不代表实时招聘市场。",
    "upgrade_notice": "升级会员可查看证据映射、资料来源和季度行动计划。"
  }
}
```

`report.mode` 是实际下发的层级，只能为 `simplified` 或 `professional`。免费用户请求 `professional` 时，实际值仍为 `simplified`，同时包含 `upgrade_notice`；专业内容绝不下发到免费响应。已有的 `report_scope` 字段保持原值和语义，不重命名、不改变枚举值。

`report.evidence` 只在专业版中返回，每一项包含：

- `type`：`personal_evidence`、`annual_source` 或 `analysis_framework`
- `title`：用户可读标题
- `detail`：与当前结论的关系
- `date`：资料发布日期；个人经历没有日期时为空字符串
- `scope`：适用岗位、地区、经验或资料范围

`analysis_framework` 仅可解释判断方法，不能作为市场事实证据。

## 权限与后端投影

后端先生成完整的内部报告，再由统一投影函数按 `report_mode` 和会员能力过滤。网页只渲染后端下发的 `report`，不会通过 CSS 或 JavaScript 隐藏已经传输的专业内容。

会员能力沿用现有会员体系：

- 年度洞察专业版使用 `industry_insight`。
- 岗位匹配、职业规划、职业测评和简历建议使用各自已存在的专业会员能力；若当前能力命名与页面不一致，新增兼容映射而不改动旧能力。
- 精简版不需要额外会员能力。

专业用户可以主动切换回精简版。该切换会重新请求接口，确保前端只保存当前实际下发的报告层级。

## 按岗位年度就业洞察

新增读取接口 `POST /api/career/annual-insights/query`，请求体包含：

```json
{
  "role_name": "数据分析师",
  "year": 2026,
  "report_mode": "simplified"
}
```

保留既有年度洞察创建与列表接口，避免破坏运营录入和已存在调用。

年度洞察资料记录扩展可选 `role_name` 字段。空值表示跨岗位通用资料；旧记录自动兼容为通用资料。查询按以下顺序筛选：同岗位资料、通用资料、岗位知识库中的稳定职责信息。若没有可核验的年度资料，结果必须明确写明“暂无可核验年度资料”，而不是生成虚构来源。

精简版显示：

- 岗位年度方向的一段简洁说明
- 3 个重点能力
- 最多 3 条可执行行动

专业版额外显示：

- 任务与交付物拆解
- 用户已验证经历与岗位要求的映射
- 能力缺口及补齐顺序
- 年度资料来源、发布日期和适用范围
- 四个季度的行动节奏

页面顶部提供岗位输入与建议列表、年份选择、精简版 / 专业版分段控件。无专业权限时，专业版控件展示升级入口并保留精简版结果。

## 桌面 HTML 界面

在所有覆盖模块的报告顶部增加统一的报告层级栏：当前层级标签、精简版 / 专业版切换、资料范围提示。精简版采用短段落和清晰行动清单；专业版增加“证据与资料”折叠区，按个人证据、年度资料和分析框架分组展示。

无资料、无会员权限和接口失败必须分别说明原因：

- 无资料：说明缺少可核验资料，并提供完善经历或调整岗位的行动入口。
- 无权限：保留精简版并说明专业版包含哪些额外内容。
- 失败：保留上次成功报告，不将错误堆栈展示给用户，并提供重试按钮。

页面文本保持简体中文；仅保留 PDF、Word、JWT、SMS、OAuth、ZIP、APScheduler、PostgreSQL、SQLite 等技术专有名词。

## 测试与验收

新增后端测试覆盖：

- 免费用户请求专业版时不接收专业证据。
- 专业用户可在同一接口获取精简版或专业版。
- 所有覆盖接口保留原字段和未传 `report_mode` 的行为。
- 岗位年度洞察按岗位、年份和通用资料正确筛选。
- 无资料时返回明确的空资料说明。

新增 HTML 单元测试覆盖：

- 年度洞察岗位选择、年份切换和报告层级请求参数。
- 精简版不渲染专业证据。
- 专业版证据卡片、来源范围和升级状态。
- 现有 API Mock 降级逻辑继续可用。

完整验收要求：后端 `pytest`、前端单元测试、H5 生产构建均通过；桌面仪表盘通过 `http://127.0.0.1:5186/premium-dashboard.html` 可访问并通过现有 `/api` 代理调用后端。
