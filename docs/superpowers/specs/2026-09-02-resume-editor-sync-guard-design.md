# 简历编辑同步与离开保护设计

## 目标

降低用户编辑简历时的中途流失和误退出风险。用户需要清楚知道内容是只保存在本机、还是已经同步到云端，并能在离开前决定保留编辑或放弃未同步修改。

## 范围

- Web 端 `ResumeEditorView` 与 `resume-editor-orchestration`。
- 保留现有 800ms 本机检查点、防抖、远程手动保存和草稿数据结构。
- 不新增后端接口、数据库字段或依赖。
- 不改变成功保存后返回草稿列表的既有流程。

## 状态与数据流

编排层暴露 `isDirty`，表示当前编辑内容是否相对最近一次服务端成功保存发生变化。

1. 服务端草稿 hydrate 完成后，`isDirty` 为 `false`。
2. 用户修改任意字段后，`isDirty` 为 `true`，并继续写入本机检查点。
3. 本机检查点成功只更新本机保存状态，不清除 `isDirty`。
4. 远程保存成功且保存期间没有新修改时，清理检查点并将 `isDirty` 置为 `false`。
5. 远程保存失败或保存期间产生新修改时，保留检查点和 `isDirty = true`，允许再次保存。

编辑器状态文案明确区分：

- 正在保存到本机
- 已保存到本机，尚未同步
- 已同步到云端
- 本机自动保存失败，请手动保存

## 离开保护

- 没有未同步修改时，返回按钮直接触发既有 `cancel` 事件。
- 有未同步修改时，返回按钮只展开编辑器内确认条，不立即离开。
- 确认条提供“继续编辑”和“放弃并返回”。
- “继续编辑”关闭确认条并恢复编辑焦点。
- “放弃并返回”清理当前草稿的本机检查点，清理成功后触发 `cancel`；清理失败时留在编辑器并显示可读错误，避免下次恢复到用户明确放弃的内容。
- 编辑器存在未同步修改时注册 `beforeunload` 保护，服务端保存成功或组件卸载后移除监听；使用浏览器原生确认，不自定义浏览器提示文本。
- 加载中或远程保存中继续沿用现有禁用/阻止逻辑。

## 可访问性与视觉层级

- 状态区域保留 `aria-live="polite"`。
- 离开确认条使用 `role="alert"`，包含清晰的当前状态和两个键盘可操作按钮。
- 危险动作使用现有 `danger-action` 语义，主路径使用现有 `text-action`/`primary-button` 语义，不新建按钮风格。
- 确认条以内联方式出现在编辑器操作区附近，不使用阻断式模态框。
- 保持现有响应式表单布局；窄屏下按钮允许换行，不能遮挡状态文案。

## 测试策略

- 在 `resume-editor-orchestration.spec.ts` 增加 hydrate、编辑、本机保存、远程保存成功/失败和保存中再次编辑的 `isDirty` 断言。
- 在 `interaction.spec.ts` 增加编辑器源码契约：状态文案、确认条分支、检查点清理、`beforeunload` 生命周期和返回事件顺序。
- 保留现有草稿检查点、编辑器校验、构建和全量测试。

## 验收标准

1. 用户输入后能看到“已保存到本机，尚未同步”，并不会被误导为云端已保存。
2. 有未同步修改时点击返回不会立即离开；放弃后检查点被清理，继续编辑则内容保持。
3. 远程保存成功后显示同步完成并可正常返回；保存失败仍保留本机内容且可重试。
4. 刷新/关闭浏览器且存在未同步修改时触发原生离开确认；无未同步修改时不阻拦离开。
5. 既有草稿加载、字段校验、快捷键、自动保存和成功回调行为保持兼容。
