# 求职工作台扩展设计

## 目标

将现有岗位查询、职业规划和简历生成 Demo 扩展为可信、可执行的求职工作台。系统必须帮助用户整理真实经历、选择目标岗位、形成补齐计划并跟踪投递过程；不得将 AI 推测、占位草稿或未经确认的量化结果作为真实经历导出。

## 范围与分期

本需求包含三个可独立交付的子系统，按以下顺序实施：

1. 可信简历工作台：真实经历证据库、AI 补全草稿逐条确认、导出前真实性检查。
2. 岗位对比与能力计划：2-4 个岗位横向比较、可解释匹配评分、7/30/90 天技能行动计划。
3. 投递行动台与交付完善：投递记录、面试复盘、提醒字段、微信小程序原生下载、离线草稿与隐私清理入口。

每一期不得阻塞现有岗位查询、草稿保存、Word/PDF 导出、职业测评或职业规划功能。

## 全局约束

- 保留匿名 `client_id` 模式，不新增登录、支付或招聘网站爬虫。
- 岗位知识仅来自既有本地知识库、已授权 API 或公开静态资料；不抓取招聘网站职位描述。
- AI 生成的项目、实习或成果必须保留 `[待确认]` 标识，直到用户将其替换为真实信息并主动确认。
- 现有 `user_draft.payload_json` 与 `ResumePayload` 必须向后兼容；旧草稿可继续打开和导出。
- 现有 CSV、SQLite 岗位知识库、模板、PDF/Word 导出接口保持可用。
- 所有新页面使用现有 Uni-App 浅色移动端样式语言，并支持 360px 宽度。

## 一期：可信简历工作台

### 数据模型

新增独立的 `resume_evidence` 表，字段如下：

- `id`：UUID 主键。
- `client_id`：匿名用户隔离字段。
- `kind`：`coursework`、`project`、`activity`、`internship`、`employment` 五类之一。
- `title`：经历标题。
- `context`：项目背景、课程场景或组织信息。
- `actions`：用户实际承担的工作。
- `outcome`：已确认的结果；未知结果留空。
- `proof_note`：可核验的证据说明，例如作品链接、代码仓库、证书、截图或联系人。
- `verified`：用户是否确认事实准确。
- `created_at`、`updated_at`：ISO-8601 UTC 时间。

证据库与简历草稿分离。草稿内仍只保留最终选中的教育、实习、项目和技能文本，以维持导出格式与旧数据兼容。

### API

- `GET /api/evidence?client_id=...`：读取当前用户的证据。
- `POST /api/evidence`：新建或更新一条证据。
- `DELETE /api/evidence/{id}?client_id=...`：删除一条证据。
- `POST /api/resume/evidence-suggestions`：基于一个目标岗位和已保存证据生成最多 3 条“可写入简历的草稿建议”；空字段保持 `[待确认]`，不补造公司、时间、数据或成果。
- `POST /api/resume/readiness`：扫描指定草稿，输出阻断项、警告项和待确认内容；仅做检查，不修改草稿。

### 前端交互

- 新增“经历证据”页面，支持按类型录入、编辑、删除和“我已确认”勾选。
- 简历填写页显示证据库入口与目标岗位相关证据数量。
- AI 建议卡片显示来源证据、建议文案、风险提示；用户可单条“写入简历”或忽略。
- 写入操作只填充当前空项目或空实习条目，不覆盖用户已有内容。
- 模板选择和导出入口在导出前显示 readiness 检查结果：阻断项禁止导出，警告项允许用户明确继续。

### 错误处理

- 证据输入缺少标题或行动描述时拒绝保存。
- 删除证据只删除证据库条目，不改写已保存草稿或已导出的文件。
- AI 服务不可用时，仍可从用户已确认的证据生成本地规则化建议。

## 二期：岗位对比与能力计划

### 数据与计算

岗位对比只使用 `role_profile`、当前职业画像、职业测评结果和用户证据中的已确认技能，不引入不透明的外部职位数据。

新增 `POST /api/career/compare`，接收 `client_id` 与 2-4 个 `role_name`，返回：

- 各岗位总匹配度及五项评分拆分。
- 共有优势、每个岗位专属优势。
- 缺失技能、进入难度、相邻岗位和风险提示。
- 每个岗位的 7/30/90 天任务，任务必须包含学习方向、可验证练习和成果沉淀方式。

### 前端交互

- 在职业规划页对岗位卡片提供“加入对比”按钮，限制最多四项。
- 新增岗位对比页，展示并列比较表、雷达式评分替代的可访问卡片、技能缺口和推荐顺序。
- 用户可将任一岗位设为“本周主目标”；该目标同步给简历和投递行动台。

## 三期：投递行动台与交付完善

### 数据模型与 API

新增 `application_tracker` 表，保存：公司、岗位、城市、来源、状态、投递日期、下一步日期、面试记录、关联草稿 ID、备注与更新时间。

提供按 `client_id` 隔离的创建、读取、更新、删除接口。状态固定为：`saved`、`applied`、`screening`、`interview`、`offer`、`rejected`、`closed`。

### 前端交互

- 新增投递行动台页面，按状态分组、支持筛选、编辑、删除和查看即将到期的下一步行动。
- 职业规划、简历编辑和岗位对比页可一键创建投递计划，自动带入岗位和当前草稿。
- 微信小程序导出使用 `uni.downloadFile` 和 `uni.saveFile`；H5 保持浏览器链接下载。
- 草稿和行动台在网络失败时写入本地 checkpoint，并在下次请求成功后提示用户同步。
- 提供“清除本机数据”入口，只清理当前设备的本地 checkpoint；后端草稿、证据和投递记录由用户逐项删除。

## 测试策略

- 后端：仓储隔离、CRUD、AI 建议不虚构事实、readiness 检查、岗位对比评分、投递状态验证与下载链接。
- 前端：数据映射、建议写入不覆盖已有文本、未确认内容告警、对比选择上限、状态筛选、本地 checkpoint。
- 构建：每一期执行后端 `pytest tests -v`、前端 `npm run test:unit`、H5 构建与微信小程序构建。

## 非目标

- 不实现用户账号、支付、社交分享、招聘网站爬虫、招聘网站账号登录、自动投递或录用概率承诺。
- 不将岗位匹配分数表示为实际录用机会、薪资保证或市场实时结论。
