# 独立 Web 求职工作台视觉与交互升级设计

## 目标

为 `web-frontend` 的独立 HTML Web 工作台建立更清晰、有层级且适合长时间操作的视觉系统，同时修复工作概览读取草稿列表时的数据格式错误。H5 预览、后端 API 和既有业务流程保持不变。

## 用户与场景

用户在桌面浏览器中反复查看简历、职业任务、岗位机会、投递记录和年度就业洞察。界面应让用户一眼找到当前的下一步行动，而不是把每个模块做成同等权重的卡片。

## 视觉方向

采用“安静的专业求职工作台”：暖白画布承载阅读和表单，深墨绿用于导航与品牌锚点，青绿色用于进度和已完成状态，低饱和蓝色表示资料与洞察，珊瑚色只用于需要立即行动的主按钮。保留圆角但控制在 8px，减少大面积阴影，以边界、留白和背景色差建立层次。

## 页面结构与交互

- 工作概览改为明确的行动优先级：一条当前状态摘要、三项可扫描的关键指标，以及连续的“整理简历、安排职业行动、记录投递”下一步路径。
- 导航保留现有信息架构，选中项采用清晰填充状态，未选中项保持低对比度，避免与主内容竞争。
- 页面标题、说明、数据区和操作区使用统一的间距节奏；表单、列表和洞察内容采用同一套表面、边界和聚焦状态。
- 按钮、标签、任务完成、模式切换、加载骨架和空状态使用短促的状态过渡；尊重 `prefers-reduced-motion`。
- 深色模式复用同一语义令牌，不单独创建另一套组件结构。

## 数据与错误处理

工作概览继续并行读取投递、草稿和职业任务。`/api/draft/list` 的响应是草稿数组，前端在边界处将其适配为内部计数模型；其他 API 响应维持当前 `{ items: [...] }` 结构。任一请求失败时仍保留可理解的中文提示，并将登录失效与一般读取失败区分开，避免把数据解析错误误写为登录错误。

## 边界

- 仅修改 `web-frontend`，不修改 H5 页面、后端 API、数据库或现有中文业务文案。
- 不新增设计依赖、图像资源或外部字体下载。
- 不改变登录、简历、职业规划、岗位、投递、洞察和账户页面的功能入口。

## 验证

- 为工作概览增加回归测试，覆盖草稿数组响应与加载失败的可读错误状态。
- 运行独立 Web 单元测试与生产构建。
- 运行一次 Impeccable 机械检查，检查改动后的 Web 源文件。
- 在本地开发服务中确认概览、浅色/深色模式和窄屏布局可访问。
