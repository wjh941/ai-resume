# 投递行动台与交付完善设计

## 目标

在不引入登录、支付、自动投递或招聘网站抓取的前提下，为匿名本地用户提供可执行的投递记录、面试复盘、草稿入口、跨平台导出下载和本机隐私清理能力。

## 范围

本期实现以下三类能力：

1. 投递行动台：以匿名 `client_id` 隔离保存投递记录，并按状态、下一步日期筛选与管理。
2. 求职工作流连接：职业规划岗位对比、简历编辑和草稿管理可创建或查看行动记录；不会自动投递。
3. 交付与隐私：H5 使用浏览器下载链接，小程序使用 `uni.downloadFile` 和 `uni.saveFile`；可清理本机 checkpoint，后端数据只通过逐项删除清理。

## 数据模型

新增 SQLite 表 `application_tracker`：

- `id`：UUID 主键。
- `client_id`：匿名客户端隔离字段。
- `company`：公司或组织名称，可为空，默认使用 `[待确认]`。
- `role_name`：目标岗位名称，必填。
- `city`：城市或地区，可为空。
- `source`：投递来源，例如官网、内推、招聘会、其他。
- `status`：`saved`、`applied`、`screening`、`interview`、`offer`、`rejected`、`closed`。
- `applied_at`：实际投递日期，可为空。
- `next_action_at`：下一步行动日期，可为空。
- `interview_notes`：面试复盘、问题与改进记录。
- `draft_id`：关联简历草稿 ID，可为空。
- `notes`：一般备注。
- `created_at`、`updated_at`：UTC ISO-8601 时间。

所有仓储读取、更新和删除都必须同时使用 `id` 与 `client_id`，禁止跨匿名客户端访问。

## 后端接口

- `GET /api/applications?client_id=...&status=...`：返回当前客户端的投递记录，支持按单一状态筛选，按下一步日期和更新时间排序。
- `POST /api/applications`：新建或更新投递记录。更新时必须归属当前 `client_id`。
- `DELETE /api/applications/{id}?client_id=...`：删除自己的记录。

状态、日期格式与必填岗位名由 Pydantic 校验；未找到或跨客户端操作返回现有 404 风格的错误响应。

## 前端交互

### 投递行动台

- 新增“投递行动台”页面，顶部显示即将到期的下一步行动数量。
- 以状态卡片筛选：全部、待准备、已投递、筛选中、面试、Offer、已结束。
- 支持新增、编辑、删除一条投递记录；删除需要二次确认。
- 每条记录展示岗位、公司、城市、状态、下一步日期、关联草稿与简短面试复盘。
- 新建记录的默认公司为 `[待确认]`，明确提示用户填入真实信息。

### 工作流入口

- 职业规划的“本周主目标”可跳转到行动台并预填岗位。
- 简历编辑页提供“加入投递计划”入口，预填当前目标岗位、所在城市和草稿 ID。
- 草稿管理页实现现有草稿的列表、打开、复制、删除和“创建投递计划”。

新建投递记录只能由用户点击确认，绝不自动调用任何招聘网站或提交简历。

### 导出下载

- 导出服务保留既有 Word/PDF 请求和下载链接格式。
- H5：使用浏览器打开或下载 URL。
- 微信小程序：使用 `uni.downloadFile` 下载临时文件，再使用 `uni.saveFile` 保存到本机文件系统；失败时显示下载链接以便用户自行处理。

### 本机数据清理

- 新增“本机数据与隐私”页面或行动台底部入口。
- 清理操作删除当前设备的 `resume_demo_checkpoint`、`resume_demo_career_planner`、咨询会话状态及本期行动台的本地草稿缓存。
- 不调用后端批量删除；已保存的草稿、证据和投递记录需在对应页面逐条删除。
- 清理前使用明确的确认弹窗，清理完成后重置内存中的简历与职业规划状态。

## 容错和离线行为

- 连接失败时，行动台新增或更新写入本机 pending 队列，并显示“本机待同步”状态。
- 页面再次打开或用户点击“重试同步”时，按创建/更新时间顺序提交队列；成功的项从队列移除。
- 后端删除失败不丢弃当前可见记录，提示用户稍后重试。
- 本机 pending 队列只保存投递表单数据，不保存 Word/PDF 二进制文件。

## 非目标

- 不实现自动投递、招聘网站账号、职位抓取、面试录音、推送通知、多人协作、服务端批量隐私删除或录用概率预测。
- 不修改既有 `ResumePayload`、`user_draft.payload_json`、CSV 格式、岗位查询和 Word/PDF 文件生成逻辑。
