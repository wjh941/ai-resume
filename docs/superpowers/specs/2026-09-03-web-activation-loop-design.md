# Web 激活闭环设计

## 目标

让用户只使用 Web 工作台即可完成第一次有效行动：创建一份简历草稿并保存，或先创建一项职业行动。首屏需要明确下一步，不能把用户转回小程序才能开始。

本批次按“首次登录后完成第一项有效行动”优化，不改变现有 API、会员权限和小程序页面。

## 范围

- 在 Web 简历中心增加“新建简历”入口。
- 使用现有 `POST /api/draft/save` 创建空白草稿；模板由用户选择，保存时仍遵守后端草稿额度。
- 新建后直接进入现有简历编辑器，并保留本地自动保存与离开确认。
- 首次登录且账户没有草稿、行动或投递记录时，在概览页显示三步激活引导：选择目标岗位、完善简历、添加第一项行动。
- 引导中的步骤直接进入对应 Web 页面，不依赖小程序。
- 对免费额度、网络失败和重复点击给出可恢复反馈。

## 不在范围内

- PDF/DOCX 导入：后端 `/api/draft/{draft_id}/import` 当前返回 501，先不在 Web 显示导入按钮。
- URL 路由、KeepAlive、跨页面结果缓存和统一错误恢复；这些作为下一批连续性改造。
- 修改后端数据结构或小程序行为。

## 数据流

1. 简历中心点击“新建简历”，打开模板选择和岗位名称输入。
2. 用户提交后调用 `saveDraft`，传入新草稿的空白 `ResumePayload`、岗位名称和模板。
3. 成功后使用返回的草稿 ID 打开现有 `ResumeEditorView`。
4. 若返回草稿额度错误，保留表单内容并提供“查看会员权益”；其他错误提供“重试”。
5. 概览页通过已有 `OverviewState.hasWorkspaceData` 判断是否显示激活引导；任一步骤完成后由下一次概览刷新反映进度。

## 空白草稿默认值

使用前端现有简历类型的完整默认结构：基本信息、目标岗位、教育、工作、项目、技能、自我评价均为空，所有 `sectionVisibility` 默认开启。默认模板为 `business`，用户可切换 `technology`、`graduate`、`analytics`。

## 体验要求

- 新建入口是简历中心首要操作，空状态不再要求“去小程序”。
- 创建按钮提交时显示加载状态并禁用重复提交。
- 成功后进入编辑器，并在标题中显示用户选择的岗位名称。
- 首次引导不遮挡主内容；每一步都有明确的单一动作，并允许直接进入职业规划或投递管理。
- 保持现有中文文案、键盘焦点和错误播报模式。

## 验证

- 单元测试覆盖空白草稿构造、创建成功、创建失败和后端额度错误。
- 组件测试覆盖简历空状态显示新建入口、创建后打开编辑器、首登引导三个入口。
- 运行 Web 全量测试和生产构建。
